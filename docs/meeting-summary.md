# 회의 요약 (1장) — MVP 구조 합의

## 한 줄 정의
첫 월급을 받은 사회초년생이 급여명세서를 이해하고, 입사 초기에 놓치기 쉬운 세금 절차·공제 요건을 챙기도록 돕는 서비스.

## 1. 타깃 (제안: 사회초년생 먼저, 이후 확장)
- **1차:** 입사 0~2년 차 직장인 (첫 월급, 첫 연말정산)
- **확장:** N잡러 (근로+부업 합산 시뮬레이션) → 인플루언서 (플랫폼 수입, 환율, 수입원 관리)
- **차별성 후보 (검증 필요):** 설명이 아니라 "내 명세서 기반 감면/공제 누락 점검 + 기한 타임라인". 삼쩜삼은 사후 환급, 명세서 설명은 블로그/서식 업체 콘텐츠가 이미 많음.

## 2. 준비된 산출물 (`docs/`)
| 파일 | 내용 | 상태 |
|---|---|---|
| `user-flow.drawio` | 명세서 업로드 → 확인 → 점검 → 할 일 (로그인/빈 결과/실패 분기 포함) | 초안, 화면 순서는 추정 |
| `erd-mvp.drawio` | 7개 테이블 (User, Payslip, PayslipField, TaxRuleVersion, CheckFinding, TaskTemplate, UserTask) | 초안, `prisma/schema.prisma`(20개 테이블)와 불일치 |
| `architecture.drawio` | 확정/제안/미정/범위 밖 색 구분 | 초안, 코드로 확인된 건 Prisma+PostgreSQL뿐 |

## 3. 오늘 정할 것
**(1) 방향**
- [ ] 타깃: 사회초년생 먼저, N잡러·인플루언서는 확장으로 둔다
- [ ] 차별성: "감면/공제 누락 점검 + 기한 타임라인"으로 간다 (아니면 대안?)
- [ ] 데모에서 보여줄 핵심 장면 1개

**(2) 기술 미정 5가지**
- [ ] 배포 위치 (서버리스 vs 일반 서버) — OCR 처리가 5~15초 걸림
- [ ] 인증 방식
- [ ] 동기 응답 vs 비동기 작업 (`job_id`)
- [ ] Vision LLM 제공자
- [ ] 알림을 MVP에 넣을지

**(3) 데이터/연동 협의**
- [ ] ERD 축소안(7개 테이블) 동의, 이후 `schema.prisma` 반영
- [ ] 사용자 입력값: 출생연도·입사일·중소기업 여부를 직접 입력받을지
- [ ] 월 단위 명세서 ↔ 계산기 연 단위 입력 연결 방식
- [ ] OCR 출력(표준 필드 14개)과 FE의 `needs_review`/`unmapped_items` 표시 방식

**(4) 일정/역할**
- [ ] MVP 데모 날짜
- [ ] PM·FE·BE·디자인·리서치 담당

## 4. 리스크
- 감면/공제 요건을 규칙 엔진이 틀리면 잘못된 안내가 됨. 규칙 수치는 아직 전부 미검증 더미 → "예상치/점검 안내, 최종 확인은 회사·국세청"으로 한정.
- OCR 정확도 목표(95%, ok인데 틀린 값 1% 이하)는 가짜 명세서 20장(필드 약 280개)으로는 통계적 근거가 약함.
- 외부 LLM에 명세서를 보내므로 마스킹, 학습 미사용 조건, 동의 안내 확인 필요.

## 5. 확인 필요
- 경쟁 서비스(삼쩜삼, 토스 등)는 앱을 직접 써서 확인하기. 이번 정리는 웹 검색 기반이라 기능이 부정확할 수 있음.
- 제안서 작성자 이름 표기 확인 (본문과 파일명이 다름).
